# Data

Everything is synthetic, generated by `data/gen_data.py --seed N`. No real people, systems, customers
or secrets appear anywhere; names, ids, addresses and timestamps are produced by the generator.

| Source | Tables | Becomes |
|---|---|---|
| logs (SIEM / audit log / directory extract) | `accounts`, `export_events`, `alerts` | Postgres database `logsdb` (infra/sources), Zetaris datasource `logsdb` |
| policy (data catalog, access policy, classification) | `datasets`, `policies`, `policy_exceptions`, `field_sensitivity` | Postgres database `policydb`, Zetaris datasource `policydb` |
| tickets (approval workflow) | `tickets` | Postgres database `ticketsdb`, Zetaris datasource `ticketsdb` |

Zetaris federates the three databases into one schema, `dexa.*` (`data/zetaris/register.py`).
`SAMPLE_MODE=true` serves the same schema from `data/sample/dexa_sample.sqlite` (`data/build_sample.py`).

`ground_truth.csv` holds the expected verdict per alert and is **never loaded into the data layer**;
only `python -m agent.main evaluate` reads it, to score the agent.

## Scenarios the generator injects (13 alerts per seed)

| Scenario | What the sources say | Expected verdict |
|---|---|---|
| S1 valid_ticket (x2) | approved ticket covers account, dataset, rows and time | compliant |
| S2a expired_ticket | cited ticket's window ended before the export | investigate |
| S2b scope_mismatch | cited ticket allows fewer rows than were exported | investigate |
| S3 policy_exception (x2) | no ticket; a role- or account-scoped exception clause covers the export | compliant |
| S4 no_authorization (x2) | rows above the no-ticket cap; no ticket, no exception | investigate |
| S5a unknown_account | exporting account is not in the directory | cannot-confirm |
| S5b missing_policy | no policy row for role x dataset | cannot-confirm |
| S5c ticket_not_found | the cited ticket id does not exist | cannot-confirm |
| S6 terminated_account | account terminated before the export | investigate |
| S7 within_policy | rows under the no-ticket cap; off-hours alert is a false positive | compliant |

Background: ~240 benign exports and ~25 unrelated tickets so the agent has to find the relevant rows.
A guard removes background tickets that would accidentally authorise an injected alert, and accounts
with a named exception are reserved for the exception scenario.

## Regenerate

```bash
.venv/bin/python data/gen_data.py --seed 7          # any seed; judges can pick one we never saw
.venv/bin/python data/build_sample.py               # SAMPLE_MODE twin
docker compose --env-file .env -f infra/sources/docker-compose.yml down -v   # reseed the Postgres sources
docker compose --env-file .env -f infra/sources/docker-compose.yml up -d
.venv/bin/python data/zetaris/register.py --skip-exists                      # (re)register in Zetaris
SAMPLE_MODE=true .venv/bin/python -m agent.main evaluate                      # score against ground truth
```

Record counts for seed 7: 40 accounts, 242 export events, 13 alerts, 8 datasets, 47 policies,
3 exceptions, 9 field classifications, ~27 tickets.

## Limits

- Policies are per role x dataset only; no per-column or per-row entitlements.
- The hours window is advisory below the no-ticket cap; the generator and the evaluator agree on that reading.
- Timestamps are naive local time in one zone.
- Licence: the generator and every generated sample are original work released with the project under Apache-2.0; they contain no third-party data.
- Pre-existing components: none. Generator, samples and ground truth were written during the build window.
